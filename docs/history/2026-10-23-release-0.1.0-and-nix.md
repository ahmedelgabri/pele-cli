# Release 0.1.0, Node security update, Nix package

## Release

- npm refused `pele-cli` as "too similar to existing package del-cli" and suggested a scope, so 0.1.0 is published as `@ahmedelgabri/pele-cli`, with `publishConfig.access: public`. The command is still `pele`.
- Two earlier publish errors were not about the name: a 403 from a token that couldn't publish, then a 404 after the CLI login expired (`npm whoami` returned 401).
- 0.1.0 was published from a laptop with a one-time password. npm only offers trusted publishing for a package that already exists, so the Publish workflow can take over from the next version, once the trusted publisher is set up on npmjs.com.
- GitHub release `v0.1.0` points at the published commit. The Publish workflow was disabled while the tag was created, so the tag didn't start a publish that would have failed, and was then enabled again.

## CI

The first theme test failed with `spawnSync /usr/bin/google-chrome ETIMEDOUT`. On a fresh runner the first Chrome launch took 8.8 s in one run and more than the 30 s timeout in another; later launches take about 1 s. The timeout is now 120 s and only catches a hung browser.

## Node security release (October 2026)

Node 26.12.1, 24.22.1, and 22.23.4 fix four high-severity CVEs. nixpkgs-unstable still had 26.12.0, so `flake.lock` points at the nixpkgs master commit with 26.12.1, which is on cache.nixos.org. `flake.nix` still tracks nixpkgs-unstable. `engines` still allows Node 22.4 and later, because the CLI doesn't use the affected areas (DNS, TLS, Brotli, `randomUUID`).

## Nix package

- `packages.default` is inline in `flake.nix`. It builds with `fetchPnpmDeps` (fetcher version 4, every platform's optional binaries), `pnpmConfigHook`, and `pnpmBuildHook`.
- The first CI build failed with a hash mismatch: macOS and Linux produced different pnpm stores. Building the fetch in an aarch64-linux container (which matched CI's x86_64-linux hash) and diffing the stores showed one difference, an empty `v11/links` directory that pnpm creates on macOS only. A `preFixup` in the `fetchPnpmDeps` call removes it with `rmdir`, so one hash now covers all systems. This is worth reporting to nixpkgs, because any `fetchPnpmDeps` package built on macOS can hit it.
- The install step deletes `node_modules` and installs runtime dependencies again. `pnpm prune` re-checks the release-age policy, which needs registry metadata the sandbox doesn't have. An install over the existing `node_modules` leaves dev packages in `node_modules/.pnpm`, about 87 MB.
- The package is 2.3 MiB, and the rest of its 208 MiB closure is Node.
- CI runs `nix build`, so a `pnpm-lock.yaml` change without a new `pnpmDeps.hash` fails.
- Don't override this flake's `nixpkgs` with `follows`: the hash depends on the exact pnpm version.
